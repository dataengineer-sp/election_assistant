# Election Assistant - Student Project Guide

This document outlines the requirements and standards for the **Election Assistant** student project. Please treat this as a high-quality academic project specification.

## Project Overview

The **Election Assistant** is an interactive educational tool designed to help students and the general public understand the voting process. The goal is to provide clear, neutral, and accessible information about elections, candidates, and voting procedures.

## Design Requirements

### User Interface (UI/UX)
- **Simplicity**: The interface must be intuitive and easy to navigate.
- **Modern Design**: Use clean, modern design principles with ample whitespace and clear visual hierarchy.
- **Responsiveness**: The layout must be fully responsive and work seamlessly on desktop, tablet, and mobile devices.
- **Accessibility**: Adhere to WCAG 2.1 guidelines (e.g., sufficient color contrast, keyboard navigation, ARIA labels).

### Visual Style
- **Neutrality**: Use neutral language and visuals. Avoid partisan symbols, logos, or color schemes that favor any political party.
- **Democracy Theme**: The design should reflect democratic values using universally recognized symbols of democracy (e.g., ballot box, voting hand, scales of justice).
- **Color Palette**: Use a professional and calming color palette (e.g., blues, greys, greens). Avoid aggressive or polarizing colors.

### Elements
- **Icons**: Use a consistent and modern icon set (e.g., Font Awesome, Material Icons) to enhance understanding.
- **Animations**: Use subtle animations for transitions and interactions. Animations should improve usability, not distract.
- **Typography**: Use clean, readable fonts. A sans-serif font for body text and a slightly more decorative font for headings is recommended.

## Technical Requirements

### Code Quality
- **Modularity**: Organize code into reusable components and functions.
- **Documentation**: All code must be well-commented, explaining the purpose of functions, components, and complex logic.
- **Best Practices**: Follow current HTML5, CSS3, and JavaScript standards.
- **Performance**: Optimize for fast loading times and smooth interactions.

### HTML
- Use semantic HTML5 elements (`<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`).
- Ensure proper heading structure (`<h1>` to `<h6>`).
- Include meta tags for accessibility and SEO.

### CSS
- Use a CSS architecture (e.g., BEM, Utility-first, or CSS Modules).
- Implement a mobile-first responsive design approach.
- Use CSS variables for the color palette and typography.

### JavaScript
- Use modern ES6+ syntax.
- Keep logic clean and separated from the DOM manipulation where possible.
- Implement event listeners efficiently.
- Handle any API calls (if applicable) with proper error handling.

## Content Structure

The application should include the following sections:

1. **Home**: Introduction to the purpose of the Election Assistant.
2. **How to Vote**: Step-by-step guide to the voting process.
3. **Voter Registration**: Information on how to register to vote.
4. **Elections 101**: Basic concepts of elections (e.g., types of elections, terms).
5. **Resources**: Links to official election authorities and non-partisan organizations.

## Submission Guidelines

The final submission should include:
1. The complete source code (HTML, CSS, JS).
2. A brief `README.md` (this file) explaining the project structure and how to run it.
3. Screenshots or a short video demonstration of the application.

## Evaluation Criteria

The project will be evaluated based on:
- Functional correctness and completeness.
- UI/UX quality and visual design.
- Code quality, documentation, and adherence to standards.
- Accessibility and responsiveness.
- Neutrality and appropriate use of democratic symbolism.
